                        RESEARCH HIGHLIGHTS APIS
================================================================================

1. ADD RESEARCH HIGHLIGHT (Create)
   Method: POST
   Endpoint: /addResearchHighlight
   Authentication: YES (Required)
   
   Request Body (JSON):
   {
     "title": "string (required)",
     "publisher": "string",
     "description": "string",
     "faculty_name": "string",
     "academic_id": "integer (required)",
     "department_id": "integer (required)",
     "year": "integer",
     "mark_as_important": "boolean (optional) - Set to true to mark as important (max 4)"
   }
   
   Response:
   Success: 201 - { "Success": true, "Message": "Research Highlight added successfully.", "data": [{ "researchHighlights_id": 1 }] }
   Error: 400/500 - { "Success": false, "Message": "Error message" }

---

2. GET ALL RESEARCH HIGHLIGHTS
   Method: GET
   Endpoint: /getAllResearchHighlights
   Authentication: NO
   Parameters: None
   
   Response:
   Success: 200 - { "Success": true, "Message": "Research Highlights retrieved successfully.", "data": [...] }
   Returns fields: researchHighlights_id, title, publisher, description, faculty_name, academic_id, department_id, year, is_important, academic, department, timestamps

---

3. GET IMPORTANT RESEARCH HIGHLIGHTS ONLY
   Method: GET
   Endpoint: /getImportantResearchHighlights
   Authentication: NO
   Parameters: None
   
   Response:
   Success: 200 - Returns only records where is_important = 1, ordered by newest first

---

13. ADVANCED FILTER - RESEARCH HIGHLIGHTS
    Method: GET
    Endpoint: /filterResearchHighlights
    Authentication: NO
    
    Query Parameters (All Optional - Can be combined):
      - keyword: string - Searches in title, publisher, description, faculty_name
      - academic_id: integer - Filter by academic
      - department_id: integer - Filter by department
      - year: integer - Filter by year
    
    Examples:
      GET /filterResearchHighlights
      GET /filterResearchHighlights?keyword=AI
      GET /filterResearchHighlights?academic_id=1&department_id=2
      GET /filterResearchHighlights?academic_id=1&year=2024
      GET /filterResearchHighlights?keyword=research&academic_id=1&department_id=2&year=2023
    
    Response:
    Success: 200 - Returns filtered results sorted by newest first (updatedAt DESC)
    
    Rules:
    - No parameters: Returns ALL records
    - Any combination of parameters allowed
    - Multiple filters use AND logic
    - Keyword search uses LIKE with wildcards (case-insensitive)

404 NOT_FOUND - Record not found

================================================================================
                            IMPORTANT NOTES
================================================================================

1. SOFT DELETE: Deleting a record marks it as deleted (delete_status = 1) but keeps it in database
   - Deleted records are not returned in GET queries
   - Can be restored using restore endpoint

2. IS_IMPORTANT LIMIT: Maximum 4 records per module can be marked as important (is_important = 1)
   - When marking 5th record as important, the oldest (by updatedAt) is automatically unmarked
   - Works across all records, not per academic or department

3. AUTHENTICATION:
   - POST endpoints (Create) require authentication (JWT Bearer token)
   - All other endpoints (GET, PUT, DELETE, PATCH) do not require authentication

4. FILTER COMBINATIONS:
   - All parameters in filter endpoints are optional
   - Multiple parameters are combined with AND logic
   - Keyword search works across multiple fields
   - Empty result returns empty array (no error)

5. ASSOCIATIONS:
   - Each publication record includes nested academic and department objects
   - Use hierarchical endpoints (getAcademicsWith*, getDepartmentsByAcademicIn*) for structured data

6. TIMESTAMPS:
   - createdAt, updatedAt automatically managed by Sequelize
   - deletedAt set only on soft delete
